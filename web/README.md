# Универсальный веб-планировщик перелётов «туда-обратно с остановкой» ✈️

Одностраничный сайт для удобного сравнения вариантов поездки. Ничего не захардкожено под
конкретный маршрут — весь текст, города, даты и событие берутся из `data.js` (`meta`).
Пример по умолчанию: Москва ⇄ Корея на концерт MCR (7 ноября 2026), ≥ 7 дней в Корее.

## Как открыть

Откройте `index.html` в браузере (двойной клик или `open web/index.html`).
Данные лежат в `data.js` (`window.TRIP_DATA`), поэтому работает прямо с `file://` без сервера.

## Что показывает

Каждый маршрут — полный round-trip с разбивкой по сегментам, временем, авиакомпанией,
ценой и ссылкой на покупку сегмента на Aviasales.

**Пересадки показаны явно** — у каждого сегмента бейдж:
- 🟢 `● прямой` — беспосадочный рейс;
- 🟠 `✈ 1 пересадка` — одна пересадка;
- 🔴 `✈ 2+ пересадок` — две и больше.

А также «🏙 длительная остановка в городе» между сегментами (это НЕ пересадка, а
запланированные несколько дней в промежуточном городе).

## Фильтры

**Направление** (что смотрим): `Туда-обратно` (round-trip, цена за всё) / `Только туда` /
`Только обратно` (односторонние билеты, цена в одну сторону).

**Пофланговая настройка** — две панели «Плечо ТУДА» и «Плечо ОБРАТНО», у каждой независимо:
- **Остановка** — без / с остановкой в промежуточном городе;
- **Пересадки** — без / с пересадками в билетах;
- **Время в пути** — макс. часов на это плечо;
- **Дней в городе остановки** — мин. длительность остановки (аналог `--min-stay` скрипта);
- **Дата вылета плеча** — диапазон дат (аналог `--leg1-dates` / `--leg2-dates`).

При «Только туда» активна панель «Туда», при «Только обратно» — «Обратно». Кнопки со
счётчиками, учитывающими выбор в остальных группах. Общие фильтры снизу: город остановки
(`--via`), макс. цена, мин. дней в пункте назначения, сортировка.

Для round-trip остановка может быть на пути туда, обратно или через один и тот же город
в обе стороны (`stopover_both`: `ORIGIN → X → HUB → X → ORIGIN`, все 4 сегмента прямые —
единственный способ получить «с остановкой · без пересадок» на направлении без
беспосадочных рейсов).

> Для Москва↔Корея беспосадочных рейсов Москва–Сеул нет, поэтому вариант «без остановки ·
> без пересадок» пуст. «С остановкой · без пересадок» существует — через города-хабы
> (Стамбул, Дубай, Пекин, Циндао и др.), где все плечи прямые.

## Как пересобрать под ЛЮБУЮ поездку

Сайт универсален — меняются только данные. Пример: Москва → Токио, 10 дней, без события:

```bash
# 1) собрать рейсы (из корня flight_scanner)
poetry run python collect_flights.py MOW MOW --intermediate HND --allow-indirect \
  --leg1-dates 2026-05-01 2026-05-05 --leg2-dates 2026-05-11 2026-05-20 \
  --output data/trip_plain.json
poetry run python collect_flights.py MOW HND \
  --leg1-dates 2026-04-28 2026-05-01 --leg2-dates 2026-05-02 2026-05-05 \
  --output data/trip_there.json
poetry run python collect_flights.py HND MOW \
  --leg1-dates 2026-05-11 2026-05-14 --leg2-dates 2026-05-14 2026-05-20 \
  --output data/trip_back.json

# 2) собрать сайт под этот маршрут
poetry run python build_web_data.py \
  --origin MOW --origin-name "Москва" \
  --hub HND --hub-name "Токио (HND)" --region-label "Япония" \
  --plain data/trip_plain.json --there data/trip_there.json --back data/trip_back.json \
  --min-stay 10 --max-stay 20 --arrive-by 2026-05-02 \
  --event-date "" \
  --title "Москва → Токио и обратно"
```

### Пересадки в плечах остановки

Плечи `ORIGIN→X` и `X→HUB` могут быть как беспосадочными, так и с пересадками
(напр. `MOW → TAS → SEL`, где каждое плечо само с пересадкой). Для этого собираются
два датасета на каждую сторону и объединяются:

```bash
# беспосадочные плечи (нужны для варианта «в обе стороны без пересадок»)
poetry run python collect_flights.py MOW ICN \
  --leg1-dates 2026-10-29 2026-11-02 --leg2-dates 2026-11-03 2026-11-06 \
  --output data/mcr_stopover_there.json
# те же плечи, но с пересадками (--allow-indirect) — больше городов и дешевле
poetry run python collect_flights.py MOW ICN --allow-indirect \
  --leg1-dates 2026-10-29 2026-11-02 --leg2-dates 2026-11-03 2026-11-06 \
  --output data/mcr_stopover_there_indirect.json
```

`build_web_data.py` объединяет `--there` + `--there-indirect` (и аналогично для `--back`).
Беспосадочный датасет при этом используется отдельно для категории «в обе стороны без
пересадок» (`stopover_both`), где все сегменты должны быть прямыми.

### Соседние аэропорты в городе остановки

По умолчанию разрешён переход между близкими аэропортами: можно прилететь в один
аэропорт города остановки, а вылететь из соседнего (≤100 км, та же страна) — напр.
прилёт в Гуанчжоу (CAN), вылет из Шэньчжэня (SZX). На карточке это показано голубой
плашкой «🛬 прилёт … → 🚗 N км → 🛫 вылет …». Управление:
`--airport-distance` (км), `--cross-country-transfers` (разрешить разные страны),
`--no-airport-transfers` (отключить). Сеть аэропортов — `data/airport_network.json`.

Все параметры: `poetry run python build_web_data.py --help`.
Ключевые: `--origin/--hub` (коды), `--min-stay/--max-stay`, `--stopover-days MIN MAX`,
`--event-name/--event-date/--event-venue` (или `--event-date ""` без события),
`--exclude` (какие города не считать остановкой). `--there ""`/`--back ""` — отключить
соответствующую категорию.
