# Changelog

## [Unreleased]

### ⚡ Кэш под-запросов сбора (origin, destination, day)

- Ответы Travelpayouts по одному под-запросу `(origin, destination, day)` кэшируются
  в SQLite (`fetch_cache`) с TTL **24 часа**. Недавно собранные под-запросы не ходят
  в API повторно — экономия запросов при пересекающихся сборах (особенно ANY-плечи,
  общие между маршрутами и цепочками планировщика).
- TTL = 24 ч подобран под сам источник: Data API отдаёт кэш цен с задержкой ~суток,
  чаще перезапрашивать бессмысленно.
- Rate-limit пауза перенесена внутрь реального обращения к API — попадания в кэш её
  не платят. Сбойные ответы (ошибка сети) в кэш не попадают, честный пустой — попадает.

## [2.3.0] - 2025-12-01

### 🎯 Переходы между аэропортами по умолчанию

- **Переходы между аэропортами теперь включены по умолчанию**: Больше не нужно указывать `--enable-airport-transfers`
- **Новый флаг `--disable-airport-transfers`**: Позволяет отключить переходы между аэропортами, если они не нужны
- **Фильтрация по странам**: По умолчанию разрешены только переходы между аэропортами одной страны
- **Новый флаг `--allow-cross-country-transfers`**: Разрешает переходы между аэропортами разных стран

### 📊 Примеры использования

```bash
# По умолчанию - переходы включены, только внутри одной страны
poetry run python aggregate_flights.py data/flights_MOW_BKK.json

# Отключить переходы между аэропортами
poetry run python aggregate_flights.py data/flights_MOW_BKK.json \
  --disable-airport-transfers

# Разрешить переходы между аэропортами разных стран
poetry run python aggregate_flights.py data/flights_MOW_BKK.json \
  --allow-cross-country-transfers
```

### 🔍 Логика фильтрации

По умолчанию при поиске переходов между аэропортами система:
1. ✅ Разрешает переходы между аэропортами одной страны (например, SVO → DME в Москве, Россия)
2. ❌ Блокирует переходы между аэропортами разных стран (например, LED, Россия → HEL, Финляндия)
3. Показывает название города для каждого аэропорта в результатах
4. Отображает расстояние между аэропортами при переходе

## [2.2.0] - 2025-11-30

### 🚌 Новая возможность: Переходы между аэропортами

Добавлена поддержка поиска рейсов с учетом переходов между близкими аэропортами. Теперь можно найти комбинации, где вы прилетаете в один аэропорт, а улетаете из другого (например, прилет в SVO Шереметьево, вылет из DME Домодедово).

### ✨ Новые возможности

- **Построение сети аэропортов**: Новый скрипт `build_airport_network.py` загружает данные об аэропортах из публичного датасета HuggingFace и вычисляет расстояния между близкими аэропортами по GPS координатам
- **Поиск с переходами**: Флаг `--enable-airport-transfers` в `aggregate_flights.py` активирует поиск с учетом близких аэропортов
- **Гибкая настройка**: Параметр `--airport-distance` позволяет настроить максимальное расстояние между аэропортами (по умолчанию 100 км)
- **Автоматическая загрузка**: Сеть аэропортов автоматически строится при первом использовании, если файл отсутствует
- **Информативный вывод**: В результатах поиска отображается информация о переходах между аэропортами с указанием расстояния

### 📊 Статистика

- Загружено 9,103 аэропортов с IATA кодами из мирового датасета
- Построена сеть из 7,550 аэропортов с близлежащими соседями
- Среднее количество близких аэропортов: 5.5 на аэропорт

### 📝 Примеры

```bash
# Построение сети аэропортов вручную (опционально)
poetry run python build_airport_network.py --max-distance 100

# Поиск с учетом переходов между аэропортами (до 100 км)
poetry run python aggregate_flights.py data/flights_MOW_BKK_20251130.json \
  --enable-airport-transfers

# Поиск с увеличенным радиусом (до 150 км)
poetry run python aggregate_flights.py data/flights_MOW_BKK_20251130.json \
  --enable-airport-transfers --airport-distance 150
```

## [2.0.0] - 2025-11-30

### 🌟 Главное изменение: Автоматический поиск направлений

Добавлена поддержка нового подхода к сбору данных о рейсах. Теперь вместо ручного указания всех промежуточных аэропортов, API автоматически находит все доступные направления.

### ✨ Новые возможности

- **Автоматический поиск всех направлений**: Параметр `--intermediate` теперь опционален
- **Гибкие параметры API**:
  - `unique=true` - уникальные направления
  - `limit=1000` - до 1000 результатов за запрос
- **Опциональный destination**: Можно собирать только исходящие рейсы из города

### 📊 Сравнение подходов

#### Старый способ:
```bash
# Нужно вручную указать все промежуточные города
python collect_flights.py MOW BKK \
  --leg1-dates 2026-02-15 2026-02-20 \
  --leg2-dates 2026-02-25 2026-03-05 \
  --intermediate IST DXB AUH DOH

# Результат: 4 промежуточных города × 6 дат × 9 дат = 216 API запросов
```

#### Новый способ (рекомендуется):
```bash
# API сам найдёт все доступные направления
python collect_flights.py MOW BKK \
  --leg1-dates 2026-02-15 2026-02-20 \
  --leg2-dates 2026-02-25 2026-03-05

# Результат: 6 дат (leg1) + 9 дат (leg2) = 15 API запросов
# Найдено: ~150-200 направлений автоматически!
```

### 🎯 Преимущества нового подхода

1. **Меньше запросов**: 15 вместо 216 (экономия 93%)
2. **Больше направлений**: ~150-200 вместо 4 указанных вручную
3. **Проще использование**: не нужно знать промежуточные аэропорты
4. **Быстрее выполнение**: меньше времени на сбор данных

### 🔄 Обратная совместимость

Старый способ с `--intermediate` всё ещё работает и может быть полезен, если вы хотите ограничить поиск конкретными городами.

### 📝 Примеры

**Автоматический поиск всех направлений:**
```bash
poetry run python collect_flights.py MOW BKK \
  --leg1-dates 2026-02-19 2026-02-19 \
  --leg2-dates 2026-02-25 2026-02-25
```
Результат: 187 направлений из Москвы + 154 направления в Бангкок = 341 рейс

**Только исходящие рейсы:**
```bash
poetry run python collect_flights.py MOW \
  --leg1-dates 2026-02-15 2026-02-20
```

**Конкретные промежуточные города (старый способ):**
```bash
poetry run python collect_flights.py MOW BKK \
  --leg1-dates 2026-02-19 2026-02-19 \
  --leg2-dates 2026-02-25 2026-02-25 \
  --intermediate IST DXB
```

### 🔧 Технические изменения

- Параметр `destination` теперь опциональный в `fetch_flights()`
- Добавлены параметры `unique` и `limit` в API запросы
- Функция `collect_leg_data()` переработана для поддержки одного origin/destination
- Обновлена CLI для поддержки опциональных параметров
- Скрипт автоматически извлекает найденные направления из результатов
